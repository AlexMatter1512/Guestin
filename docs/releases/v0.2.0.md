# oshost v0.2.0

Compared with version tag `v0.1.3` (`f178c35`). This release includes the complete pending changes from both development worktrees.

## Access codes and structure management

- Add time-unrestricted staff access codes for cleaners, laundry and other recurring access. A separate Staff codes view has no calendar, defaults to non-revoked codes, and retains usage counts, sharing, editing, pauses and revocation. Single-use rules, disabled doors and unresolved actions still apply; breakfast allowances keep their own limits.
- Add a Non revoked filter to ordinary access codes.
- Hide internal notes in the code form until explicitly enabled, preserving existing notes when the form is hidden.
- Let owners deactivate and reactivate structures. Inactive structures disappear from everyday views, guest links and connector requests stop working, and historical data remains in the database and backups. Notification retention pauses while a structure is inactive.
- Let owners permanently delete structures and related database records, or individual access codes and their usage/notification history, after typed confirmation. Destructive structure/code changes cannot overlap an in-flight operation. Existing backup files are unaffected.

## Collaborator accounts and security

- Rename the staff account role to collaborator, keeping it distinct from staff access codes. Owner and admin refer to the same unrestricted role.
- Add independent collaborator permissions for ordinary access-code creation/management, new doors, booking connector use, and staff access-code creation/management. The server checks permissions on each authenticated request; changes refresh active browsers. Switching a code's type requires both code permissions.
- Let owners edit collaborator permissions, delete collaborators, or promote them to owner. Account management, connector configuration, permanent deletion, backups and database wiping remain owner-only. Existing-door configuration and device tests also require an owner.
- Owners can only delete their own accounts, and another owner must remain. Account deletion revokes sessions and push subscriptions while preserving shared data and access codes.
- Add password changes for owners and collaborators under Your account. The current password is required; a successful change revokes all sessions. Login and password changes share persistent account backoff across IP addresses and restarts. Guest and authentication routes have separate per-IP limits.

## Upgrade and deployment notes

- Back up the database and encryption keys before upgrading. Schema version 7 automatically migrates existing staff accounts to collaborators and preserves their previous code-creation and connector capabilities. Newly invited collaborators start without permissions until an owner grants them.
- API consumers must handle `role: "collaborator"`, effective account permissions, the new `staff` code flag and inactive structures. Legacy guest codes and active structures retain their behavior.
- The supplied Compose configuration now enables `TRUST_PROXY=1`. The reverse proxy must overwrite `X-Real-IP`, and the backend must be reachable only by that proxy. Use `TRUST_PROXY=0` for direct connections. Public deployments require HTTPS; setting `ORIGIN` alone does not enable TLS.

## Releases and validation

- Every pushed Git tag runs CI and publishes a Docker image after successful checks. SemVer tags additionally create a GitHub release using reviewed notes. Stable versions update version, minor and latest Docker tags; prereleases and build-metadata versions do not update the latter aliases.
- Add AGENTS.md instructions to review the full changes since the previous release and commit release notes before tagging.
- Local validation: 104 passing tests, TypeScript/Svelte checks, production builds for both apps, browser flows for collaborator permissions, promotion, deletion, password changes and staff codes, workflow lint, and secret scanning. Upgrade tests cover the version-6 database layouts from both worktrees.

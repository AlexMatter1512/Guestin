# Guestin v0.5.0

Compared with the previous stable release, `v0.4.0` (`4e3f0ef`). This release includes the changes shipped on `edge` through `build-20261118-guest-page`, the KrossBooking room planner, and the latest access-code activity and staff permissions.

## Guest pages and host navigation

- **Other → Guest Page** lets you choose an accent color and show a logo uploaded in Properties. Edit the introduction and single-use instructions in Markdown with heading, bold and underline controls, a rendered preview and restore-default buttons. Each message supports independent translations of up to 5,000 characters and a configurable fallback language.
- The server keeps the last 10 guest page settings versions per property. **Open guest page** previews saved settings with sample doors. Demo buttons never send device requests.
- On mobile, pick a favourite under **Other** for the shortcut beside **+**, including a specific configured connector. On desktop, **Other** expands in the sidebar, Doors and Access codes have their own create buttons, and main content is centered. Team, Guest links, Email delivery and Reports use a single page heading.
- Access codes are grouped by arrival or departure day. Search opens inline, date and guest/staff selectors sit together, and shared calendar dialogs handle date and range inputs. Owners can choose a workspace display format for host, guest and breakfast pages. API dates stay in ISO format.
- The partner breakfast page updates live and supports date ranges, English and Italian, and optional browser notifications. Existing breakfast links redirect to the new page.

## Booking connectors

- Open a connector by selecting its row. KrossBooking opens a room planner spanning today through the end of the month. Choose another date range, inspect bookings and matched doors, or find reservations by guest name or arrival date. When a phone number is available, share or download a vCard with a configurable contact name.
- AI screenshot extraction supports Google Gemini, OpenAI and Anthropic Claude. Choose a provider, enter an API token, fetch its model list and select a model with image input. Existing Gemini configurations continue to work. Imported reservation details remain drafts until you review and save the access code.

## Activity and staff permissions

- Activity has separate **Guest** and **Staff** tabs, and every access code has its own timeline. Notifications open the relevant door or code when available. Accepted door requests display **Door opened**. The integration records provider acceptance and cannot confirm physical door state.
- Staff notifications identify the person who made the change. Code updates include added or removed doors, previous and new validity times in the property’s time zone, and changes to single-use access, labels, code type or breakfast allocation. Notes and links are identified by field name to protect their contents. Saving an unchanged code does not create an update notification.
- **Edit guest page** and **Test door openings** are independent collaborator permissions in **Settings → Team**. They default to off for new and existing collaborators. Authorized door testers can mark uncertain tests as checked. Door tests still require confirmation and an idempotency key. Saved device credentials remain owner-only.
- Guest Markdown restricts raw HTML to underline markup and sanitizes links. The breakfast live connection rechecks authorization and sends refresh signals without guest or access-code details.

## Upgrading from v0.4.0

- The app and Docker repository are now **Guestin** and `alexmatter/guestin`. Use `alexmatter/guestin:latest` for stable updates, `alexmatter/guestin:edge` for each tag build, or `alexmatter/guestin:0.5.0` to pin this release. The bundled Compose file defaults to `edge`. Set `GUESTIN_IMAGE_TAG=latest` for the stable channel.
- Preserve the existing database volume and runtime encryption keys. The Compose service is now `guestin` and defaults to reusing `oshost_oshost-data`. Set `GUESTIN_DATA_VOLUME` if your old stack used a different volume. Existing `DB_PATH` values, legacy databases, session cookies and legacy JSON imports remain supported. New JSON exports use Guestin format names. See [upgrading and backups](../UPGRADING.md).
- SQLite migrations 10 and 11 add shared date display and server update-channel settings. **Settings → Server** shows the installed build and checks the selected channel. Installing a server update still requires pulling and recreating the container.
- CI publishes the AMD64 and ARM64 image and then updates both channel manifests with its digest. Those manifests describe the image that was successfully pushed.
- Guestin is now distributed under the MIT license. The documentation is organized by setup, daily use and self-hosting, and the landing site has isolated interactive demos.

## Validation

- 178 automated tests, TypeScript and Svelte checks, and production builds for both apps passed.
- Browser smoke tests passed for connectors and the KrossBooking planner, collaborator permissions, mobile navigation, guest page editing and activity. The tests used isolated data, mocked providers and fake door adapters.
